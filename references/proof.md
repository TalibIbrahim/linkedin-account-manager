# Proof (look like a really good dev, truthfully)

Clients trust evidence. Build the evidence ladder in this order:

1. **Case studies (2+).** Template: Problem → Constraints → What I built (stack, key decisions) → Result (real numbers: users, speed, cost, time) → What I'd do next → Link/demo. Output as an editable `.pptx` carousel (1080x1350, 6-8 slides, one idea per slide) plus a text version for the Featured section and posts. Build it via `/mnt/skills/public/pptx/SKILL.md` if present, else write the carousel as a JSON spec (one entry per slide) and run `python scripts/make_pptx.py spec.json case-study.pptx`; if that script fails too, present the spec as a plain-text build spec (one slide per section). Use only facts the user confirms; mark unknown results as "needed" and ask.
2. **Live demos.** Working URL, 30-60s screen recording script, 3 clean screenshots. Broken demo = negative proof; check them.
3. **GitHub polish.** Pin 4-6 best repos; each README: one-line pitch, screenshot/GIF, features, stack, setup, live link. Clean commit history, no secrets, a profile README with the offer and contact.
4. **Portfolio site/landing page.** One page: offer, 2-3 case studies, process, testimonials, contact/booking. Fast, mobile-friendly.
5. **Social proof.** Recommendations from past collaborators, teammates, professors, club leads, employers. Give a 3-line ask script that suggests specific points to mention. After each finished project, ask for a testimonial within 48 hours.
6. **Authority signals** (real ones): talks, community leadership, open-source PRs, technical write-ups, certifications, achievements.

Gap analysis: list what exists vs missing, then schedule the top gap as this week's task.
